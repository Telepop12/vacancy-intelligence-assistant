# Vacancy Intelligence Assistant

Python CLI-приложение для анализа вакансий уровня **CIO / Директор по ИТ / CTO / CDTO**.

Принимает текст вакансии, сравнивает с профилем кандидата и формирует структурированный отчёт:
Match Score, рекомендацию, ключевые совпадения, риски, вопросы к HR, шаблон ответа и советы по резюме.

---

## Установка

```bash
cd vacancy_ai_assistant
pip install -r requirements.txt
```

Требуется **Python 3.11+**.

### Модели

По умолчанию проект использует гибридный маршрут:

- обычный анализ, Career Match, варианты резюме и письма — локальная
  `qwen3.8:27b` в Ollama;
- подготовка к интервью, вопросы по её блокам и ресёрч компании —
  `gpt-6-astra` через OpenAI Responses API.

Модели и маршруты меняются в `config/llm.yaml`. Для подготовки добавьте
`OPENAI_API_KEY` в `.env` (см. `.env.example`). При запуске в Docker Compose
контейнер обращается к Ollama на хосте через `host.docker.internal`.

## Использование

### Анализ из файла

```bash
python main.py --file data/sample_vacancy.txt
```

### Через pipe (stdin)

```bash
cat data/sample_vacancy.txt | python main.py
```

### Интерактивный ввод

```bash
python main.py
# Введите текст вакансии, завершите строкой «.»
```

### Все параметры

```
python main.py [--file PATH] [--profile YAML] [--output DIR] [--no-registry]

  -f, --file PATH      Путь к .txt файлу с вакансией
  -p, --profile YAML   Профиль кандидата (по умолчанию: config/candidate_profile.yaml)
  -o, --output DIR     Директория для отчётов (по умолчанию: output/)
  --no-registry        Не добавлять запись в output/registry.csv
```

## Модель скоринга

Score считается как взвешенная сумма по 6 категориям. Внутри категории достаточно найти ~50% ключевых слов для получения полного балла — частичное совпадение засчитывается.

| Категория | Вес | Что проверяет |
|---|---|---|
| `role_fit` | 25 | Название роли и стратегические сигналы (CIO, ИТ-стратегия…) |
| `management_scope` | 20 | Масштаб управления (команда, бюджет, портфель проектов…) |
| `digital_ai_transformation` | 20 | Цифровизация, AI, ERP/1С, BI, MDM, автоматизация |
| `infrastructure_and_it_ops` | 15 | ITSM/ITIL, ИБ, инфраструктура, облако, DevOps |
| `business_scale` | 10 | Масштаб бизнеса (сотрудники, бюджет, холдинг…) |
| `industry_fit` | 10 | Предпочтительные отрасли (производство, логистика…) |

**Риски** формируются только по явным red flags: junior/middle роль, отсутствие управленческого контура, sales-роль, нежелательная отрасль, слишком короткое описание.

## Настройка профиля кандидата

Отредактируйте `config/candidate_profile.yaml`:

- `scoring_groups.<name>.keywords` — ключевые слова категории
- `scoring_groups.<name>.weight` — вес категории (сумма должна быть 100)
- `red_flags.<name>` — список фраз, при совпадении которых генерируется риск

## Career Match Layer

Resume-aware vacancy analysis — **Option B** (parallel scoring):

| Score | Источник | Описание |
|---|---|---|
| **Keyword Score** | Rule-based, детерминированный | Keyword matching по 6 категориям |
| **Career Match Score** | LLM, full career analysis | Полная карьерная траектория + transferable competencies |

### Принцип

Вместо ATS-анализа последнего места работы — оценка всей карьеры:
- Переносимые (transferable) компетенции: инфраструктура → enterprise systems thinking → трансформация
- Скрытая релевантность: кибербезопасность → governance, DevOps → операционная эффективность
- Медленно устаревающий опыт: лидерство, PMO, трансформация, M&A интеграция

### Web UI

`/match` — новый раздел. Принимает вакансию + резюме (параллельно).
Результат: два score рядом (Career Match vs Keyword), Trajectory Analysis,
Transferable Competencies, Strategic Strengths, Risks & Gaps, итоговое заключение.

### Что улучшает

| Кейс | Keyword Score | Career Match Score |
|---|---|---|
| 29-летний CIO на Head of AI (без AI keywords) | 23 — ПРОПУСТИТЬ | 60+ — УТОЧНИТЬ/ЗАПУСТИТЬ |
| CIO на роль с другим стеком (SAP vs 1С) | 40 | 70 — ОТКЛИКАТЬСЯ |
| Карьера: инфраструктура → CDTO | MEDIUM | HIGH fit |

### Архитектура

```
VacancyInput + ResumeProfile
        ↓
career_match() → CareerMatchResult
        ↓
  career_match_score (LLM)
  keyword_score (rule-based)
  transferable_competencies
  trajectory_analysis
  strategic_strengths
  risks_and_gaps
  final_recommendation
```

## Resume Intelligence Layer (Phase 1)

Анализ executive-резюме для построения structured intelligence profile кандидата.

### Запуск

```bash
# Web UI
http://localhost:8000/resume

# Python API
from agents.resume_intelligence import analyze_resume, load_resume
text, src_type = load_resume(Path("resume.docx"))
profile = analyze_resume(text, source_file="resume.docx", source_type=src_type)
```

### ResumeProfile schema

| Поле | Описание |
|---|---|
| `executive_summary` | 2-3 предложения: кто этот человек professionally |
| `strategic_positioning` | 1 sentence executive positioning statement |
| `professional_archetype` | CIO / CDTO / CAIO / Transformation Executive / … |
| `trajectory_markers` | Карьерные траектории (3-5) |
| `strongest_assets` | Топ-5 executive strengths |
| `weak_visibility_areas` | Что есть в опыте, но плохо видно в CV |
| `ai_signals` | Обнаруженные AI/ML сигналы |
| `transformation_experience` | Трансформационный опыт |
| `governance_signals` | ITSM/ITIL/ISO/кибербезопасность |
| `technology_domains` | Cloud, ERP, AI/ML, Security и т.д. |

### Positioning Dashboard (5 индикаторов)

| Индикатор | HIGH | MEDIUM | LOW |
|---|---|---|---|
| AI Positioning | ≥5 AI сигналов | 2-4 | <2 |
| Transformation Positioning | ≥4 сигнала | 2-3 | <2 |
| Executive Positioning | C-level scope, enterprise scale | — | — |
| Operational Depth | ≥3 scope сигнала (команда, бюджет) | 1-2 | 0 |
| Strategic Visibility | ≥4 business impact сигнала | 2-3 | <2 |

### Executive Framing Analysis

Система оценивает **язык CV** — операционный vs стратегический:

| Level | Описание |
|---|---|
| `operational` | Преобладает: сопровождение, поддержка, мониторинг, help desk |
| `technical` | Технический язык без executive framing |
| `managerial` | Управленческий, но не стратегический |
| `executive` | Стратегический язык, результаты, ownership |
| `strategic` | Board-level язык, P&L, трансформация, governance |

Executive Framing Score (0–100) = доля executive language signals из всех detected.

### Executive Reframing Opportunities

LLM предлагает 3 конкретных примера как переформулировать operational язык в executive framing:

```
Было: "внедрён мониторинг серверов"
Suggested: "создана observability platform для обеспечения непрерывности критичных бизнес-процессов"
Reason: executive framing акцентирует business impact, а не техническую задачу
```

### Composite Organizational Scale

2000+ сотрудников больше не определяется как "mid". Используется cumulative scoring:

| Signal | +pts |
|---|---|
| 10,000+ employees | +4 |
| 5,000+ employees | +3 |
| 2,000+ employees | +2 |
| Holding / group structure | +2 |
| PMO / project portfolio | +1 |
| Multi-site / distributed | +1 |
| Complex ERP landscape (3+ systems) | +1 |
| Board / governance level | +1 |

`enterprise` ≥ 3 pts · `holding` ≥ 6 pts

### Industry Detection v2

Контекстная фильтрация устраняет false positives: если keyword появляется рядом с "для заказчика", "клиент", "поставщик для" — индустрия не засчитывается.

### Explainability

Каждый вывод подкреплён `evidence` — конкретными фрагментами из CV. В Web UI раскрываются "Evidence fragments" под каждым блоком сигналов. Scale показывает rationale с enumerated signals.

### Поддерживаемые форматы

`.docx` (python-docx) · `.pdf` (pypdf) · `.txt` · `.md`

### Future compatibility

Архитектура готова для: resume adaptation, LinkedIn profile generation, interview prep, executive bio generation, outreach templates.

## Автопоиск вакансий на hh.ru

Раздел **🔍 Поиск hh.ru** (`/search`) — автоматическое обнаружение и первичная оценка вакансий.

### Как работает

```
Поисковые запросы (config/hh_search.yaml)
        ↓
hh.ru: id вакансий по каждому запросу (поиск по названию)
        ↓
Полные описания — только для НОВЫХ вакансий (история в output/hh_search_state.json)
        ↓
Rule-based триаж: score + рекомендация по каждой (без LLM — бесплатно и быстро)
        ↓
Таблица, отсортированная по score → «Полный анализ» запускает LLM-конвейер по клику
```

### Канал доступа к hh.ru

Используются **публичные страницы hh.ru**: JSON-LD JobPosting со страницы вакансии,
поиск — парсинг выдачи. Запросы идут в одной cookie-сессии с вежливыми паузами.

Официальный API не используется: в декабре 2025 hh.ru закрыл анонимный доступ
к вакансиям и прекратил поддержку API для соискателей (доступ выдаётся только
под задачи работодателей). Поддержка `HH_ACCESS_TOKEN` в коде оставлена на случай,
если политика hh.ru изменится.

### Анализ по ссылке

На странице «Анализ вакансии» поле **URL вакансии** принимает ссылки `hh.ru/vacancy/…`
(включая региональные зеркала) — метаданные и полный текст подтягиваются автоматически.
Прочие URL обрабатываются универсальным HTML-парсером.

### Настройка

`config/hh_search.yaml`: список запросов, регион (`area: 113` — Россия, `1` — Москва),
глубина выдачи и лимит новых вакансий за запуск.

## Варианты резюме для hh.ru

Раздел **🗂️ Варианты резюме** (`/variants`).

Особенность hh.ru: откликаться можно только резюме, которое уже существует в
аккаунте (новое висит на модерации ~10 минут), поэтому «резюме под каждую
вакансию» не работает. Вместо этого система готовит контент для **постоянных
вариантов резюме** под архетипы ролей:

| Вариант | Фокус |
|---|---|
| CIO | классическое ИТ-руководство: стратегия, бюджет, команда, инфраструктура |
| CTO | разработка: инженерные команды, архитектура, DevOps, поставка |
| CDTO | цифровая трансформация + управление данными (MDM, BI, ROI) |
| CAIO | ИИ-направление: стратегия ИИ, генеративный ИИ, ИИ-агенты |
| Универсальный | широкий профиль для нестандартных ролей |

Для каждого варианта генерируются: заголовок резюме, блок «О себе», список
ключевых навыков, акценты по каждой позиции опыта, пояснение «что изменено»
и честные пробелы под архетип.

**Железное правило: факты не выдумываются.** Источник — каноническое резюме
(`config/resume_variants.yaml → resume_file`); LLM только переакцентирует
реальный опыт. Блоки копируются в резюме на hh кликом (click-to-copy),
готовые документы сохраняются в `output/resume_variants/*.md`.

## Пакет отклика

Кнопка **«Пакет отклика»** в таблице результатов поиска (`/package/hh/{id}`).

Для конкретной вакансии генерируется:

1. **Сопроводительное письмо — рамка «3+3»** (единственный русскоязычный
   формат с 05.10.2026, ~220–280 слов): «Прошу рассмотреть моё резюме на
   позицию …» → абзац «Мой профиль — 20+ лет … на стыке IT, Digital, Data и
   AI» → «Ключевые компетенции и достижения, релевантные позиции:» ровно
   три пункта «Компетенция. — Доказательство» → «Чем конкретно могу усилить
   компанию на этой позиции:» ровно три буллета по тем же осям → резюме и
   встреча → подпись. Оси по семейству роли: CIO — ИТ-стратегия / Операции /
   Партнёрство с бизнесом; CDTO — Трансформация / Портфель / Экономика;
   CAIO — Портфель AI / Операционная модель AI / Экономика; CTO —
   Архитектура / Поставка и эксплуатация / Экономика и команда. Эталон —
   личный файл `data/resume/cover_letter_reference.md` (вне git, строки «>»
   — комментарии): генератор повторяет структуру, тон и подпись (подпись
   подставляется детерминированно), а компетенции, доказательства и
   предложения пишет под вакансию; цифры и компании — только из резюме и
   факт-базы, стаж в письме — «20+ лет» по решению заказчика. Названия
   инструментов, которых нет в вакансии, заменяются классом (`stray_tool_names`).
   Под письмом — «три требования → три доказательства» и «три дела после
   выхода» с осью каждого для проверки. Главный пер-вакансийный артефакт на
   hh.ru, уходит с откликом мгновенно;
2. **Рекомендация, каким вариантом резюме откликаться** (из постоянных
   вариантов раздела «Варианты резюме») с обоснованием;
3. **«Что зеркалим»** — таблица соответствий «требование вакансии → факт
   кандидата», чтобы проверить письмо перед отправкой.

Источники фактов: каноническое резюме + факт-база `data/resume/facts.md`
(публикации, pet-проекты, детализация позиций). Правило то же: никакой
выдумки. Пакеты сохраняются в `output/applications/`.

## Пакет подготовки к интервью

Кнопка **«Подготовка к интервью»** в карточке вакансии и в избранном
(`/prep/{id}`). Работает независимо от отклика. Сборка идёт в фоне, страница
показывает прогресс по десяти этапам: сначала ресёрч компании с веб-поиском,
затем вопросы; последние пять разделов собираются параллельно, обычно 15–25
минут. Модель — Opus 5.5 (задаётся в `config/llm.yaml`). Резюме и факт-база
уходят в модель общим блоком с кешированием: первый этап записывает их в кеш,
остальные читают по 10% цены. Результат сохраняется в
`output/prep/`; ссылка «перегенерировать» собирает пакет заново, кнопка
«дособрать» — только недостающие разделы.

Промпты опираются на базу знаний `data/interview_kb/` (реальные вопросы
ИТ-директорам, стоп-слова работодателей, паттерны отбора C-level) через
загрузчик `agents/interview_kb.py`; под каждым блоком — источники.

**Схема ответов «Моё понимание + мой опыт»** (с 21.10.2026). На собеседовании
хотят слышать не только опыт кандидата, но и его понимание. Где прямой опыт
есть, ответ ведёт опыт, а «моё понимание» — общий принцип. Где в резюме
пробел, ответ ведёт понимание: как это делается, 2–3 подхода или
архитектурных паттерна с плюсами и минусами, и только потом реальный пример
из опыта, если он про тот же механизм. Притягивать опыт за уши запрещено.
Вопросы, где ответ ведёт понимание, помечены значком «понимание».

Состав пакета:

1. **О компании** — ресёрч открытых источников с веб-поиском: масштаб и
   география, собственники, менеджмент, структура бизнеса, финансы,
   ИТ-проекты и ИТ-ландшафт, цифровизация и AI, закупки ИТ-услуг. У каждой
   темы — ссылки на источники; адреса сверяются с тем, что реально вернул
   поиск, а тема без подтверждённого источника помечается «не подтверждено».
   Ниже — как использовать факты на интервью и что выяснить на встрече.
   Сжатая справка уходит в вопросы интервьюера, вопросы работодателю, «что бы
   вы улучшили», структуру и персонал, рассказ о себе и план 100 дней.
   Веб-поиск стоит $10 за 1000 запросов, на пакет уходит до десяти.
   Поэтому справки складываются в **архив компаний** (`output/companies/`):
   при генерации система сначала ищет компанию там (по бренду, без
   «ООО» и прочих форм) и идёт в веб-поиск, только если записи нет или она
   старше полугода. Кнопка «Обновить ресёрч» в разделе делает свежий поиск
   мимо архива и обновляет запись.
2. **Рассказ о себе на 3 минуты** — три части: кто я и что я; опыт,
   образование, достижения; что ищу и куда хочу двигаться. Около 400 слов.
3. **Вопросы интервьюера от утверждений резюме** (в жанре банка реальных
   вопросов) и **общие и поведенческие вопросы HR** с учётом стоп-слов
   работодателей.
4. **Структура и персонал** — оценка ИТ-структуры под вакансию и компанию
   (направления, численность, штат или аутсорс) как гипотеза с основанием и
   вопросами для проверки; вопросы «Структура и команда» (создать, принять,
   развивать, сократить, оптимизировать) и «Управление подчинёнными»
   (задачи, спор, критика, развитие, наказание, увольнение).
5. **Истории и управленческие кейсы** — два конфликта, провальный проект,
   ошибка руководителя, изменённый процесс и четыре кейса (масштабирование,
   эффективность, реструктуризация, антикризис). Источник — личный файл
   `data/resume/stories.md` (шаблон с подсказками создаётся автоматически,
   файл вне git). Пока он пуст, пакет показывает каркасы из проектов резюме
   с пометкой «каркас из резюме» и вопросами, что нужно вспомнить; выдумки
   за факт не выдаются.
6. **План первых 100 дней** в трёх блоках и устный ответ на «что будете
   делать в первые месяцы».
7. **«Что бы вы улучшили у нас?»** — до 6 гипотез со стороны, каждая с
   опорой («вакансия», «компания», «отрасль»), формулировкой вслух по схеме
   наблюдение → гипотеза → вопрос, проверочным вопросом и опорой в опыте
   кандидата; плюс рамка ответа, контекст отрасли и до 5 конкретных практик.
   Внешний поиск получает требования вакансии и факты из «О компании».
   Практика проходит отбор только с цитатами из обоих входов, описанием
   процесса, применения, метрикой и реальным URL из поиска. В раскрываемом
   блоке видны основания применимости и источники. Кеш на 14 дней зависит
   от вакансии, справки о компании и модели; резюме в поисковый этап не идёт.
   Без найденных практик остаются гипотезы по вакансии и компании с пометкой
   об ограничении поиска, вместо выдуманных отраслевых трендов.
8. **Повестка 2026** — ИБ, ИИ на практике, импортозамещение: позиция и
   кейс с цифрами по каждой теме.
9. **Блиц «экзамен»** — 8–10 коротких вопросов на определения и цифры под
   домен вакансии.
10. **Спросить двойника** — свой вопрос, ответ от вашего лица на ваших
    фактах. Кроме того, в двенадцати блоках есть окошко **«Спросить ИИ»**:
    вопрос уходит модели с контекстом именно этого блока и в его жанре (в
    спарринге это новый раунд, в блице короткий ответ, в историях оформление
    вашего рассказа, в разделе «О компании» — ответ со свежим веб-поиском и
    ссылками). Ответы сохраняются под блоком, попадают в `.md`, лишние
    удаляются крестиком.
11. **Вопросы работодателю** — обязательно про внутреннего кандидата,
    причину появления вакансии, цели на 90 дней, полномочия и ФОТ, этапы
    впереди; где уместно — со ссылкой на факты из ресёрча компании.
12. **Purple Team** — спарринг по болевым зонам: атака → защита → судья →
    отточенный ответ.
13. **Чего не говорить** — общий чек-лист словами работодателей и 3–5 пунктов
    лично под кандидата.
14. **Шпаргалка «10 минут до звонка»** (`/prep/{id}/cheatsheet`) — одна
    страница под печать из готового пакета, без обращения к модели: что
    упомянуть о компании, рассказ о себе, три самых неудобных вопроса с
    ответами, пять цифр, вопросы работодателю, блиц, «что бы вы улучшили»
    вслух, «не говорить».

Разделы «Как проходит процесс» и «Козыри и болевые зоны» сняты 21.10.2026:
они получались типовыми. Козыри и болевые зоны по-прежнему считаются — ими
питаются спарринг, вопросы работодателю и «чего не говорить».

Свободные составные вопросы получают ответ от общего к частному: короткий
тезис и 2–5 смысловых блоков с заголовками. Для вопросов про ИТ-бюджет
разделяются достаточность суммы, эффективность расходов и рыночность цен:
сопоставимые отраслевые ориентиры → результаты проектов и эксплуатации →
структура затрат внутри ИТ → анализ рынка и конкурентных процедур → вывод.
Затраты по ресурсам и по назначению рассматриваются отдельно, без двойного
учёта. Доля ФОТ оценивается вместе с моделью ИТ, аутсорсингом и результатами.
Нормативные проценты не выдумываются; R&D не приравнивается ко всему
ИТ-бюджету. Справка о компании
передаётся в контекст ответа с сохранением годов показателей.

В мини-кейсе ответ начинается с существенных уточнений или явно названных
допущений, затем идут расчёты и условный вывод. В количественных вопросах
для CEO модель получает задачу дать 2–4 полезные числовые опоры с выводами.
Недостающие исходные данные и отраслевые проценты не придумываются.

Проверенные вручную ориентиры хранятся в `data/interview_kb/benchmarks.yaml`.
Для свободного вопроса загрузчик выбирает карточки по теме и отраслевому
контексту, передаёт источник, период, базу расчёта и ограничения. Это локальное
чтение без нового поиска и дополнительного вызова модели. После срока
`review_after` карточка исключается до повторной проверки. Первая подборка
покрывает ИТ-бюджет: два межотраслевых показателя APQC и опрос CereCore/CHIME
2026 года. Они не считаются нормативами для российской медицинской сети.

## Vacancy Intake Pipeline

Единый ingestion-слой для вакансий из любых источников. Analysis layer никогда не работает напрямую с raw text — все входящие данные проходят нормализацию через `agents/intake.py`.

### Поддерживаемые источники

| Source Type | Метод | Описание |
|---|---|---|
| `text` | `from_text()` | Raw text string (stdin, paste) |
| `file` | `from_file()` | .txt / .md / .json файл |
| `html` | `from_html()` | Raw HTML с парсингом тегов |
| `json` | `from_json()` | Structured JSON (hh.ru API-совместимый) |
| `url` | `from_url()` | Stub — future Playwright/requests |

### VacancyInput schema

```python
@dataclass
class VacancyInput:
    source_type:         SourceType        # text | file | url | html | json
    source_name:         str               # filename или "stdin"
    raw_text:            str               # оригинальный текст
    normalized_text:     str               # clean input для анализатора
    title:               str               # extracted job title
    company:             str               # extracted company name
    location:            str               # extracted location
    salary:              str               # extracted salary
    url:                 str
    detected_language:   str               # ru | en | mixed
    ingestion_timestamp: datetime
    intake_confidence:   IntakeConfidence  # HIGH | MEDIUM | LOW
    confidence_notes:    list[str]         # причины снижения confidence
    metadata:            dict
```

### Normalization pipeline

1. Unicode NFC нормализация
2. Unescaping HTML entities (`&nbsp;` → пробел и т.д.)
3. Удаление HTML-тегов (если есть)
4. Удаление zero-width и soft-hyphen символов
5. Схлопывание пробелов и пустых строк
6. Удаление декоративных строк (`---`, `===`, `•••`)
7. Strip каждой строки

### Intake Confidence

| Уровень | Условие |
|---|---|
| **HIGH** | Текст ≥ 300 символов, заголовок найден, есть стандартные секции |
| **MEDIUM** | Текст 100–300 символов или нет заголовка/секций |
| **LOW** | Текст < 100 символов, ошибка парсинга, файл не найден |

### Future integrations

Добавить новый источник = написать одну функцию `from_X()` + добавить `SourceType.X`. Analysis layer не меняется.

Планируемые адаптеры: hh.ru API, LinkedIn, Telegram, Gmail, Google Docs.

## Decision Intelligence Layer

Финальный слой синтеза, объединяющий все сигналы в единое executive-level заключение.

### Архитектура синтеза

```
Deterministic Scoring
  ↓
Semantic LLM Analysis (Ollama / OpenAI)
  ↓
Evolutionary Potential Evaluation
  ↓
recommendation_engine.synthesize()   ← Decision Intelligence Layer
  ↓
Final Recommendation + Explainability
```

### Новые поля анализа

| Поле | Описание |
|---|---|
| **strategic_rationale** | Объяснение итоговой рекомендации с учётом всех факторов |
| **career_risks** | Конкретные карьерные риски: operational trap, weak authority, delivery-heavy |
| **career_opportunities** | Конкретные возможности: board access, AI ownership, ROI visibility |
| **best_case_scenario** | Лучший сценарий карьерного развития через эту роль |
| **worst_case_scenario** | Реалистичный худший сценарий — чего следует опасаться |
| **strategic_validation_questions** | Вопросы для проверки реального upside перед откликом |

### Логика синтеза рекомендации

Рекомендация определяется **не только** по score. Пример:

```
score = 20  (rule-based: ПРОПУСТИТЬ)
evolutionary_potential = High
executive_visibility = High
AI_trajectory_relevance = High

→ recommended_action = ЗАПУСТИТЬ В РАБОТУ
```

### Explainability

Все рекомендации explainable — система показывает:
- `strategic_rationale`: почему именно такая рекомендация
- `career_risks` / `career_opportunities`: полный баланс рисков и возможностей
- `best_case_scenario` / `worst_case_scenario`: диапазон исходов
- `strategic_validation_questions`: что уточнить перед принятием решения

Никаких black-box решений: каждая рекомендация подкреплена конкретными аргументами.

### Fallback-безопасность

`recommendation_engine.synthesize()` работает в двух режимах:
1. **LLM подключена** — валидирует и дополняет модельный вывод, не перезаписывая его
2. **LLM недоступен** — генерирует детерминированный контент на основе scoring данных

Сбой LLM не ломает систему: все 6 новых полей всегда заполнены.

## Evolutionary Potential Analysis

Помимо keyword scoring система оценивает **стратегический потенциал** вакансии как точки входа в AI leadership — даже если роль формально не является CIO/CDTO.

### Рекомендации

| Статус | Смысл |
|---|---|
| ✅ **ОТКЛИКАТЬСЯ** | Прямое совпадение профиля, score ≥ 70 |
| ⚠️ **УТОЧНИТЬ** | Частичное совпадение, нужны уточнения |
| 🚀 **ЗАПУСТИТЬ В РАБОТУ** | Невысокий keyword fit, но высокий эволюционный потенциал |
| 🚫 **ПРОПУСТИТЬ** | Низкий fit, нет стратегического потенциала |

### Факторы Evolutionary Potential

| Фактор | Сигналы |
|---|---|
| **Organizational Visibility** | Прямой доступ к CEO / board, защита проектов |
| **AI Maturity Signals** | Новое AI-направление, ранняя стадия adoption |
| **Scope Expansion** | Ownership AI-инициатив, кросс-функциональное влияние |
| **ROI Gravity** | Measurable ROI, автоматизация, снижение затрат |
| **Executive Exposure** | Участие в стратегических сессиях |

**High** (3+ сигнала) → `ЗАПУСТИТЬ В РАБОТУ` &nbsp;|&nbsp; **Medium** (1–2) → `УТОЧНИТЬ` &nbsp;|&nbsp; **Low** → без изменений

## Архитектура анализаторов

```
core/
├── analyzers/
│   ├── base.py               ← BaseAnalyzer (ABC)
│   ├── rule_based.py         ← RuleBasedAnalyzer (keyword scoring)
│   ├── hybrid.py             ← HybridAnalyzer (rule-based + LLM placeholders)
│   └── claude_analyzer.py   ← совместимый адаптер единого LLM-шлюза
├── recommendation_engine.py ← Decision Intelligence (synthesis + fallback)
└── analyzer.py              ← analyze() — публичная точка входа
```

По умолчанию `analyze()` обращается к локальной Ollama; при её недоступности
остаётся **HybridAnalyzer** с rule-based scoring и плейсхолдерами LLM-полей.

### Подключение LLM

1. Установите и запустите Ollama; модель по умолчанию — `qwen3.8:27b`.
2. Скопируйте `.env.example` в `.env` и добавьте `OPENAI_API_KEY` для
   подготовки к интервью и веб-ресёрча.
3. Проверьте маршруты в `config/llm.yaml` и запустите
   `docker compose up -d --build`.

Обычные генераторы работают локально. Только вызовы с `purpose="prep"`
отправляют резюме, вакансию и факт-базу в OpenAI API.

### LLM-поля в `VacancyAnalysis`

| Поле | Описание |
|---|---|
| `semantic_summary` | Общее семантическое резюме вакансии |
| `role_level_fit` | Соответствие уровню роли (C-level vs middle management) |
| `strategic_vs_operational_balance` | Баланс стратегических и операционных задач |
| `target_role_alignment` | Соответствие целевым позициям кандидата |
| `authority_signals` | Сигналы реальных полномочий (бюджет, команда, совет директоров) |

## Web UI / Docker

### Запуск через Docker (рекомендуется)

```bash
docker compose up --build
```

Приложение будет доступно по адресу: **http://localhost:8000**

Отчёты сохраняются в `output/` на хосте (примонтирован как volume).

```bash
pip install -r requirements.txt
uvicorn web.app:app --reload --port 8000
```

### Smoke test (пока сервер запущен)

```bash
python web/smoke_test.py
```

Проверяет 5 ключевых сценариев: health check, главная страница, анализ вакансии, обработка пустого ввода, наличие рекомендации в результате.

web/
