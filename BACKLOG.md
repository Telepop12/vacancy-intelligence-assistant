# BACKLOG.md — план развития по спринтам

Рабочий формат: заказчик ставит задачу → спринт реализуется → **приёмка
заказчиком** → коммит → следующий спринт. Спринт не начинается, пока предыдущий
не принят. Этот файл — план перед глазами: что делаем сейчас, что следом,
что сознательно отложено и почему.

Статусы: **▶ в работе** · **⏭ следующий** · **⏳ ждёт события** · **💤 отложено
заказчиком** · **✅ принято** · **⛔ отклонено**.

Обновляется при закрытии спринта и при появлении новых задач.

## ▶ В работе: спринт «Подготовка 2.0» — принят 21.09.2026, обкатка продолжается

**Статус 21.09.2026 (вечер).** Реализовано в полном составе (см. CHANGELOG
2026-09-21) и принято заказчиком по первой вакансии из избранного
(«функционально выглядит неплохо», «супер», «заработало»); два замечания
приёмки закрыты в тот же день: подсветка оглавления при прокрутке и раздел
«Что бы вы улучшили у нас?». Закоммичено. Дальше — «погонять на реальных
вакансиях»: второй пакет по вакансии из базы (Сбер), затем решить по
пост-фильтру имени лаборатории и фоновой сборке (п. 6a).
Отличия от плана ниже: истории берутся из личного файла
`data/resume/stories.md` (пока он пуст — каркасы из резюме), блок «Как
проходит процесс» строит модель на выдержках базы, а не только
детерминированно; вызовов Sonnet — восемь. Для приёмки в браузере контейнер
нужно пересобрать: `docker compose up -d --build`.

**Зачем.** Генератор подготовки к интервью (`agents/interview_prep.py`) сейчас
опирается на общие представления о том, как проходят собеседования. Собрана
база знаний `data/interview_kb/` (~100 первичных источников): как реально
устроен отбор C-level в РФ, какие вопросы задают дословно, что сами
работодатели советуют кандидатам. Задача — связать базу с генератором.

**Состав работ:**

1. `agents/interview_kb.py` — загрузчик выдержек из базы. Файлы целиком в промпт
   не подать (290 КБ ≈ 100K токенов на вызов): модуль отдаёт срезы на 8–15 КБ —
   банк вопросов по темам, паттерны процесса, правила, стоп-слова. Поиск профиля
   компании по названию работодателя из вакансии.
2. Усиление существующих промптов ориентирами из базы: интервьюер получает банк
   реальных вопросов как образец жанра; HR-блок — стоп-слова Сбера, Билайна,
   Альфы; вопросы работодателю — блок про полномочия, ФОТ, «почему появилась
   вакансия», внутреннего кандидата.
3. Новые разделы пакета подготовки:
   - **«Как проходит процесс и кто передо мной»** — по компании, если она есть
     в базе; иначе типовой сценарий C-level (4–10 этапов, 2–6 месяцев, решает
     первое лицо, референсы у 5–7 человек).
   - **Самопрезентация** в двух форматах: 1–3 минуты (скрининг) и 5–7 минут
     (финал/знакомство с командой), по схеме «задача → роль → решение →
     обоснование → измеримый результат → выводы», с бюджетом, командой,
     географией.
   - **Истории и кейсы**: два конфликта, провальный проект, ошибка лидера,
     изменённый процесс + четыре управленческих кейса (масштабирование,
     эффективность, реструктуризация, антикризис).
   - **План первых 100 дней** в трёх блоках — как ответ на «что будете делать
     в первые месяцы» и как возможная презентация.
   - **Повестка 2026**: информационная безопасность, ИИ на практике,
     импортозамещение — по одному кейсу с цифрами на каждую тему.
   - **Блиц «экзамен»**: 8–10 коротких вопросов на определения и цифры.
   - **«Чего не говорить»**: негативный чек-лист из слов самих работодателей.
   - **Шпаргалка «10 минут до звонка»** — одна страница из готового пакета,
     без обращения к модели.
4. Источники под каждым блоком (откуда взят ориентир).
5. Тесты: офлайн-проверки загрузчика и структуры пакета.

**Критерий приёмки:** заказчик открывает подготовку по реальной вакансии из
избранного и подтверждает, что новые разделы полезны и не дублируют друг друга.

**Стоимость:** вызовов Sonnet на пакет станет 6–7 вместо 4. Работы — 2–3 сессии.

**Источник плана:** `output/market_reality_2026-09.md` (разбор статьи о найме
2026 и страниц Т-Банка), `data/interview_kb/README.md`.

## Очередь

### 0. Мини-этап «Актуализация LLM-контура» ✅ выполнен и принят 22.09.2026

**Зачем.** Заказчик заметил, что запросы к модели уходят не в самых
актуальных версиях. Инвентаризация 22.09: модель `claude-sonnet-5`
(`config/llm.yaml`, `core/llm.py`) — это текущее поколение Sonnet, менять
не нужно; устарело окружение и форма запроса: в контейнере SDK `anthropic`
1.7.0, на хосте 0.116.0, в `requirements.txt` слабый пин `>=0.40.0`;
`ARCHITECTURE.md` §3.7 всё ещё называет `claude-sonnet-4-6`; вызовы идут без
стриминга при `max_tokens` до 16 000 — при обрыве сети 22.09 три этапа
пакета упали по таймауту («Request timed out»).

**Состав (один-два часа, без изменения функциональности):**
1. Сверить список моделей через Models API (`client.models.list()`), решить,
   какая модель на какой тип вызова: Sonnet 5 остаётся по умолчанию; для
   этапов подготовки рассмотреть Opus 5 ($5/$25 против $2/$10) — решение
   заказчика по деньгам.
2. Пин `anthropic>=1.7,<2` в `requirements.txt`, обновить SDK на хосте до
   1.x (1.x собран на `httpx2`, свой `httpx.Client` не подходит — в
   `core/llm.py` уже учтено через `DefaultHttpxClient`).
3. `core/llm.py::call_json` — перевести на `client.messages.stream(...)` с
   `get_final_message()`: убирает HTTP-таймауты на длинных ответах;
   проверять `stop_reason` (`max_tokens` → повтор с ужатием, `refusal` →
   понятная ошибка); адаптивное мышление у Sonnet 5 включено по умолчанию,
   `output_config.effort` уже передаётся правильно.
4. Поправить `ARCHITECTURE.md` §3.7 (модель, SDK, стриминг), CLAUDE.md.
5. Прогон `-m llm` тестов на живом ключе + один пакет подготовки.

**Приёмка:** пакет по реальной вакансии собирается без таймаутов, тесты
зелёные, в документации актуальные модель и версия SDK.

**Итог 22.09.** Models API подтвердил: `claude-sonnet-5` — текущий Sonnet
(доступны также `claude-opus-5`, `claude-fable-5-1`). Решение заказчика:
пакет подготовки — на Opus 5 (карта `models: {prep: claude-opus-5}` в
`config/llm.yaml`), остальные генераторы — на Sonnet 5. SDK на
хосте поднят до 1.7.0, пин `anthropic>=1.7,<2`. Шлюз переведён на стриминг
с проверкой `stop_reason` (`qa/test_llm_gateway.py`). Документация
(ARCHITECTURE §3.7, CLAUDE.md) обновлена.

### 2. Спринт B — «Первый контакт» ⏭

Довести цепочку до отправки.

- Письмо с сопроводительным и резюме на HR-адрес после апрува в интерфейсе
  (SMTP, черновик показывается заказчику, отправка по кнопке). HR-адреса уже
  собраны обходчиком в `config/target_companies.yaml`.
- Отдельная заготовка письма для executive search (по данным исследования, на
  C-level это один из главных каналов).
- Учёт отправленного: кому, когда, по какой вакансии.

**Ограничение:** полностью автоматическая рассылка отвергнута заказчиком.
Каждое письмо уходит только после явного подтверждения.

### 3. HireSeeker как источник радара ⏳

Агрегатор `hireseeker.ru` собирает Telegram-каналы, LinkedIn, карьерные сайты и
hh в одном месте — закрывает канал, которого у нас нет. Раздел
«Лиды/CTO/CDO» отдаётся обычным HTML со ссылками на первоисточник, обход
разрешён в `robots.txt`. Подключается как ещё одна «компания» обходчика; фильтр
названий отсеет тимлидов. Заказчику имеет смысл подписаться на их бота.

### 4. Парсер Авито в радар ⏳

Ждёт первого письма: заказчик настраивает 2–3 сохранённых поиска в Авито Работе
с уведомлениями на почту, по структуре письма пишется третий парсер радара.
Скрейпинг Авито отвергнут (антибот).

### 5. Переезд на мини-сервер ⏳

Когда заказчик поднимет машину с гипервизором.

- Docker-стек переезжает как есть; volumes `output/`, `config/`, `data/`.
- VPN с раздельным маршрутом: Anthropic и LinkedIn через туннель, hh и зона
  `.ru` напрямую. Варианты: аппаратная коробка с маршрутизацией по доменам
  (с поправкой на DPI), прокси-сплит в контейнере, ВМ-шлюз.
- Доступ с телефона через Tailscale или ZeroTier: у приложения нет авторизации,
  наружу не выставлять.
- `.env` переносится руками, бэкап `output/`.

### 6. Международный трек, этап 2: система под англоязычный формат ⏭

Профиль и резюме готовы (спринт «Международный профиль» принят 20.09.2026).
Состав:

- **Языковой режим генераторов.** Сейчас во всех промптах жёсткое правило
  «отвечай исключительно на деловом русском». Нужен параллельный набор правил
  и выбор языка пакета по вакансии.
- **Флаг «требует релокации» в скоринге**, чтобы международные вакансии не
  смешивались с московскими в общей ленте.
- **Англоязычный пакет отклика**: письмо и рекомендация варианта резюме.
- **Отдельный блок подготовки к интервью на английском.** Заказчик сообщил, что
  опыт устных интервью на английском минимальный, поэтому блок строится как
  тренажёр, а не как справка: речевые заготовки под типовые вопросы,
  самопрезентация с проговоркой вслух, разбор вопросов, которых нет в России
  (visa status, notice period, «why relocate», ожидания в net-выражении для
  Залива), панельный формат, произношение отраслевых терминов.
- **Источники**: getmatch, AgileFluent, релокационные каналы.

Ждёт от заказчика: LinkedIn-алерты на CIO / IT Director / Digital
Transformation Director по целевым локациям.

### 6a. Фоновая сборка пакета подготовки ✅ выполнено и принято 22.09.2026

в памяти процесса (один воркер uvicorn); после рестарта контейнера
незавершённая сборка забывается. Перенос механизма на пакет отклика и
автопоиск — отдельным пунктом, если понадобится.

## ⛔ Отклонено (не предлагать повторно)

| Что | Почему |
|---|---|
| API hh.ru | Анонимный доступ закрыт в декабре 2025, соискательский API прекращён, регистрация приложений только для работодателей. Проверено живым запросом: 403. |
| Автоматическая отправка откликов | Запрещено правилами hh и отвергнуто заказчиком: роботы отправляют такие отклики в корзину. |
| Скрейпинг аккаунта LinkedIn | Риск блокировки профиля. Разрешены только гостевые публичные страницы малыми порциями. |
| Скрейпинг Авито | Антибот. Вместо этого — подписки с письмами. |
| Google-таблицы как источник истины | Двусторонняя синхронизация требует сессии Claude, конфликты. Допустим односторонний экспорт. |
| Прокси через домен заказчика | hh банит по поведению, а не по адресу; риск для личного домена. |
| Пагинация и API обходчика карьерных страниц | C-level вакансии публично почти не размещаются: обходчик остаётся дешёвой сигналкой, вкладываться в глубину незачем. |
